# ADR-0002: Poseidon parameterisation, domain separation and tree conventions

- Status: accepted (M1), pending cryptographer sign-off (design Q5)
- Date: 2026-11-03

## Context

The same hash has to be computed in three places: the Noir circuits, the Rust
reference/SDK, and the pool program on-chain, where only `sol_poseidon` is
cheap. Design §2 warns that Noir's stdlib Poseidon is *not* compatible with
`sol_poseidon`. The doc writes `Poseidon_DS("polypus.note.v1", …)` but leaves
the domain-separation mechanism open.

## Decision

1. **Parameters:** Poseidon over the BN254 scalar field with **circomlib
   parameters** (x^5, `t = n+1`, `R_F = 8`, circomlib `R_P` table, zero
   capacity). Implementations:
   - `light-poseidon` 0.4 `new_circom(n)` (Rust);
   - `sol_poseidon` `Bn254X5` big-endian (on-chain);
   - `noir-lang/poseidon` v0.4.0 `bn254::hash_n` (Noir).
2. **Arity ≤ 12** for anything recomputed on-chain (`sol_poseidon`'s limit).
   The largest hash, `pi_hash`, has 11 inputs.
3. **Domain separation by a leading tag input:** `tag(s)` is the big-endian
   integer of the ASCII string, e.g. `polypus.note.v1`. All strings are ≤ 31
   bytes, so the tag is a canonical field element, trivially reproducible in
   any language, and carries the version (`.v1`). Hashes of different arities
   are already different permutations; the tag also separates same-arity uses.
4. **Merkle nodes are untagged** `H_2(l, r)` to save on-chain CU. The other
   2-input hashes are `H_2(T_AK, ·)` and `H_2(T_RCM, ·)`. A collision with a
   node would need an inner node equal to the small constant tag, which is a
   Poseidon preimage problem.
5. **Empty leaf `Z_0 = 0`**, `Z_{i+1} = H_2(Z_i, Z_i)` (same as Light's trees).
   A commitment equal to 0 needs a Poseidon preimage of 0. `0` is never a
   valid root: unused root-history slots are zero, and both the Rust reference
   and the pool reject root = 0.
6. **Field encoding:** 32-byte big-endian canonical everywhere. Decoders reject
   values ≥ p.

## Verification

- The Rust KAT `H_2(1,2) = 0x115cc0f5…4417189a` (circomlib) passes.
- `circuits/polypus_notes` tests reproduce the Rust outputs for all arities
  1–12, all tags, `ak`, `owner`, `asset_id`, a note commitment, a nullifier,
  the empty root and a Merkle path (vectors generated by `gen-vectors`).
- The pool program's tests compare `sol_poseidon` against the same vectors
  (programs/).
- 10,000 random differential cases check the full kernel relation, Rust vs
  Noir (docs/benchmarks.md).

## Consequences and risks

- 2026 cryptanalysis (design §8.1) breaks *reduced-round* Poseidon and
  Poseidon2, not full-round circomlib Poseidon. Hash agility comes from the
  version suffix in every tag plus the note `version` field. A v2 hash means
  new tags, a new tree, and a migration by spending old notes into it.
- `poseidon` in Noir is a library, not a black box, so each `H_2` costs about
  560 R1CS constraints after Sunspot (`docs/benchmarks.md`). The 52 Merkle
  hashes dominate the kernel's cost.
